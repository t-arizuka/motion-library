## コンセプト
この会話で制作した「光がつくる、新しい体験。」のイメージ画像を参考に、
右上から差し込む広く柔らかな白青色の自然光、深いネイビー背景、
左側の文字載せ余白、画面下部の控えめな光だまりを目標とする。

**参考画像と実WebGL描画は別のもの。** 参考画像を背景テクスチャとして貼っていない。
撮影した光のような空気感は目標だが、完全再現・納品品質とは現時点では評価しない。

## ファイル構成
- `index.html` — 既存エディタ共通CSSを参照したPC／スマホ・文字表示切り替えの検証画面
- `renderer.js` — 自作WebGL1静止レンダラー、GLSL取得・GPUエラー表示・リサイズ再描画
- `light-rays.frag` — 原作ではなく本プロジェクトで新規作成したGLSLの光束シェーダー
- `README.md` — この品質検証記録

## シェーダーの作り方
- 極端な光線の均等配列を避け、角度・幅・強度が不規則な12本の柔らかい光束を重ねる
- 低周波ノイズと複数の広いボリューム光を組み合わせ、物理的に厳密ではない光散乱を近似
- 右上の画面外にソフトな光源を配置し、左側には暗い余白を確保
- わずかな画素ディザでバンディングを抑え、Bloomは使用しない
- 床面の弱い光だまりは擬似的なもので、実在する床・反射面をシミュレートしてはいない
- 写真やAI生成画像、React Bitsのソースを取り込んでいない（権利・再配布の問題を避ける）

## 検証したこと
- EGL + Mesa llvmpipe (OpenGL ES 3.2) で**公開するGLSLと同等のシェーダー処理を実際にコンパイル・描画**。GLエラー0。
- デスクトップ相当 1200×675、スマホ相当 390×844でPNGの静止画を取得。
- JavaScriptの構文検査、GLSLのデータ形状、PC/スマホ・テキストON/OFF UIの構造確認。
- リサイズ時に1フレームだけ描画するWebGL1ロジック。再生用の継続ループは入れない。
- 既存エディタCSSを参照するが、正式ギャラリーとWordPress配信用ファイルは変更しない。

## まだ確認していないこと
- 公開ページの実Chrome/SafariでのGPU描画・モバイル端末負荷の計測
- 実ブラウザでのテキストの視認性と光の素材感
- 参考画像と比べたビジュアル品質のユーザー承認
- アニメーション・色／速度GUI・WordPress埋め込み

ローカルのChromiumは管理上WebGLが無効だったため、ブラウザ内のWebGL実描画は未検証。
ただし**MesaのオフスクリーンOpenGL ESによる実シェーダー描画は成功**しており、
単なる構文検査や画像生成と混同しないよう区別して記録する。

- [ ] 右上の光が不自然な扇形・放射状の線にならない
- [ ] 霧・光の階調が写真のように自然
- [ ] 文字との構図がPCとスマホで成立する
- [ ] チープな発光やBloom頼みに見えない
